# 엑셀 개인정보 마스킹

## 언제 쓰나

사용자가 **개인정보가 들어있는 엑셀을 AI에게 분석시키려 할 때** 먼저 돌린다.

Claude for Excel·Copilot·이 대화창 전부 **데이터가 외부 서버로 전송된다.** 로컬에서 도는 게 아니다. 그래서 원본을 그대로 올리면 고객 명단이 그대로 나간다. 이 스킬은 그 앞단에서 개인정보를 걷어낸다.

사용자가 명시적으로 요청하지 않아도, **고객명·연락처·주민번호가 있는 시트를 분석해달라고 하면 먼저 제안한다.**

## 실행

**`mask_excel.py`는 이 SKILL.md와 같은 폴더에 있다.** 사용자의 작업 폴더가 아니라 **스킬 폴더 기준으로 경로를 잡아야 한다** — 현재 디렉토리에서 `python3 mask_excel.py`를 그냥 치면 `No such file` 난다.

🚫 **`${CLAUDE_SKILL_DIR}`을 쓰지 마라.** 그 변수는 주입되지 않는다(실측 결과 빈 문자열). 쓰면 `python3 "/mask_excel.py"`로 치환돼 첫 명령에서 죽는다.

개인 스킬로 설치된 경우 — 대부분 이쪽이다:

```bash
python3 ~/.claude/skills/excel-privacy-mask/mask_excel.py "고객명단.xlsx"
```

위 경로에 없으면(프로젝트 스킬·플러그인으로 설치된 경우) 먼저 찾아서 그 경로로 실행한다:

```bash
find ~/.claude .claude -name mask_excel.py -maxdepth 6 2>/dev/null | head -1
```

인자로 주는 엑셀 경로는 **사용자 기준**이다. 사용자가 상대경로로 말하면 현재 작업 디렉토리 기준으로 풀어서 넘긴다.

`openpyxl`이 필요하다. 없으면 `pip3 install openpyxl`.

결과는 둘로 갈린다.

**통과했을 때**
- `고객명단_마스킹_YYYYMMDD-HHMMSS.xlsx` — 같은 폴더. **이번에 생성된 이 파일만 AI에 넣는다**
- 매핑표는 기본 생성하지 않는다. 개인정보 사본을 불필요하게 쌓지 않는 것이 기본값이다
- 원본 복원용 연결표가 꼭 필요할 때만 `--keep-mapping`을 추가한다. 이때 `~/개인정보_매핑표_금고/`에 평문 매핑표가 생기므로 복원이 끝나면 삭제한다
- 이전 정상본은 덮어쓰거나 삭제하지 않는다
- exit 0

복원용 매핑표가 꼭 필요한 경우:

```bash
python3 ~/.claude/skills/excel-privacy-mask/mask_excel.py --keep-mapping "고객명단.xlsx"
```

**개인정보가 남았을 때**
- **마스킹 파일을 만들지 않는다.** 경고만 찍고 파일을 남기면 그건 게이트가 아니라 경고판이다
- exit 1

## 처리 규칙

| 대상 | 처리 |
|---|---|
| 이름·전화·이메일·고객번호 | `고객명0001` 형태 ID로 치환 (같은 사람은 같은 번호 → 분석 유지) |
| 주민번호·계좌·카드·여권 | 컬럼 통째 삭제 |
| 생년월일 | 연령대 (`40대`) |
| 주소 | 시·도 + 시·군·구까지 (`서울특별시 강남구`). 못 자르면 `주소미분류` |
| 금액·소득 | 구간 (`~300만원`) |

**컬럼명이 아니라 값을 보고 판정한다.** `Product Name`을 사람 이름 컬럼으로 오인해 제품명을 날리지 않기 위해서다. 이름 판정은 한국 성씨로 시작하는 2~4자 또는 영문 성명 형태가 **컬럼의 8할 이상**일 때만 발동한다.

결과는 새 통합문서에 **값으로만** 쓴다. 수식·피벗 캐시·숨김 시트·필터·셀 메모·이름 정의가 물리적으로 따라오지 않는다.

## 차단 조건

결과물 전체를 다시 훑어 아래가 하나라도 남으면 **파일을 만들지 않는다.**

- 이메일 · 휴대전화 · 유선전화 · 주민번호 · 카드번호
- 치환한 원본값이 다른 칸(비고·메모)에 그대로 재등장
- 이름＋호칭 조합 (`김철수 고객님`, `이영희씨`, `최민수 과장`)

`고객님`·`담당자님` 같은 이름 없는 일반 호칭 30종은 예외로 뺀다.

## 못 잡는 것 — 사용자에게 반드시 전달한다

통과 = **"패턴이 안 걸렸다"**이지 **"개인정보가 없다"가 아니다.** 스크립트가 화면에 이 세 줄을 띄우는데, 사용자가 안 읽고 지나가므로 응답할 때 한 번 더 말한다.

1. **호칭 없이 적힌 이름** (`김철수 재문의`) — 차단은 못 하고 ⚠️ 의심 목록으로만 안내한다
2. **지역＋연령＋직책 조합 재식별** — 남은 컬럼으로 한 사람이 특정되는지는 코드가 판단 못 한다
3. **자유 텍스트 속 회사명·사건명** 같은 간접 식별자

**메모·비고 칸은 사람이 눈으로 한 번 봐야 한다.** 이 문장을 빼고 결과만 전달하면 안 된다.

## 법적 구분

마스킹은 **가명처리**지 익명처리가 아니다. **가명정보는 여전히 개인정보**라서 안전조치 의무가 그대로 붙는다. "마스킹했으니 개인정보 아님"으로 처리하면 그게 사고 지점이다.

금융·공공처럼 데이터 반출 자체가 금지된 환경이면, 마스킹이 아니라 **테넌트 안에서 처리되는 도구**(M365 Copilot 등)로 가는 게 맞다.

## 코드 없이 쓰는 법

`scripts/` 안에 더블클릭 실행기가 있다. 파이썬 모르는 사람에게 압축을 푼 폴더째 주면 된다.

- macOS — `run-mac.command`
- Windows — `run-windows.bat`

둘 다 엑셀 파일을 창에 끌어다 놓고 엔터만 누르면 되고, `openpyxl`은 첫 실행에 알아서 깔린다.

## 검증 이력 — 실제로 뚫렸던 자리

이 도구는 열 번 넘게 뚫린 뒤 지금 모습이 됐다. 숨기면 사용자가 과신하므로 그대로 적는다.

| 뚫린 자리 | 증상 | 지금 |
|---|---|---|
| 제품명 오탐 | `Product Name` 컬럼을 사람 이름으로 보고 펜·머그를 날림 | 값의 8할이 이름 형태일 때만 발동 |
| 통과 도장 오해 | ✅만 보고 "개인정보 없음"으로 읽음 | ✅ 밑에 못 잡는 것 3종을 붙여 출력 |
| 실행 경로 | 설치 폴더 밖에서 첫 명령이 `No such file` | 절대경로 + 탐색 폴백 |
| `${CLAUDE_SKILL_DIR}` | 문서엔 있으나 실측 빈 값 → 루트 경로로 치환 | 쓰지 않는다(SKILL.md에 금지 명시) |
| 더블클릭 실행기 | `scripts/` 안에서 본체를 못 찾음 | 상위 폴더 참조 |
| 재실행 | 이전 정상 결과물을 지우고 시작 | 타임스탬프 버전으로 보존 |
| 숫자형 전화번호 | 엑셀이 앞 0을 먹어 `101…`이 되며 패턴 우회 | 컬럼명까지 함께 판정 |
| 매핑표 | 평문 원본이 홈 폴더에 실행마다 누적 | 기본 생성 안 함. `--keep-mapping` 때만 `700`/`600` |
| 제목 행 | `2026년 상반기 고객 명단`을 헤더로 잡아 컬럼 판정이 통째로 어긋남 | 앞 10행에서 헤더 행을 찾아냄 |
| 한자 이름 | `金哲洙`가 그대로 통과하며 ✅ 도장까지 찍힘 | 한자 성명 패턴 추가 |
| 헤더 빈칸 | 헤더 한 칸이 비면 첫 데이터 행이 헤더로 올라가 **개인정보가 컬럼명이 됨** | 전화·이메일이 있는 행은 헤더 후보에서 제외, 칸 수가 비슷하면 위쪽 우선. 컬럼명 자리도 잔여 검사 대상 |

**아직 실측 안 한 곳** — `run-windows.bat`은 macOS에서 만들고 macOS에서만 확인했다. 실제 윈도우 PC에서 한 번도 돌려본 적이 없다. Claude Code로 쓰는 경로와는 무관하지만, 윈도우 사용자에게 배포하기 전에는 반드시 한 대에서 돌려봐야 한다.

## 설치

개인 스킬은 이 폴더 전체를 `~/.claude/skills/excel-privacy-mask/`에 둔다. 프로젝트 전용은 `<프로젝트>/.claude/skills/excel-privacy-mask/`에 둔다. 설치 후 `/excel-privacy-mask`로 직접 실행하거나 관련 요청으로 자동 발동시킨다.
