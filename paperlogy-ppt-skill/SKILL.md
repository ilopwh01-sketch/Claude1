# 페이퍼로지 PPT 스킬

이 번들 하나로 **같은 디자인이 매번 그대로 나온다.**
원칙만 적힌 문서가 아니라 실제 디자인 토큰 + 정본 템플릿 + 배경 이미지 + 검사 코드가 함께 들어 있다.

핵심은 하나다. **사람의 의지에 기대지 않고 코드가 검사한다.**
줄표를 안 쓰겠다고 다짐하는 대신, 줄표가 있으면 빌드가 실패한다.

## 0. 대전제 — 원칙을 스스로 줄이지 않는다

PPT는 **원칙이 이미 정해진 분야**다.
"이 슬라이드엔 이건 없어도 되겠지", "채팅 장면이니 좀 줄여도", "카피는 빨리 대충" 같은 판단으로
**원칙을 축소·생략·변형할 재량이 없다.** 아래 원칙은 전부 기본값 ON이고, 빼는 건 만드는 사람이 명시로 정할 때만이다.

목표는 하나다. **두 번 고치지 않게 한 번에 완주한다.**
카피 확정 → 시각화 → 게이트 ERROR 0 → 레이아웃 다양화 → 실제 PowerPoint 렌더 확인 → 실문자 오타 확인까지
한 번에 끝내서, 받아본 사람이 더 손댈 게 없게 뽑는다.
"이 정도면 됐겠지"에서 멈추는 것이 두 번째 수정 요청을 부른다.

## 1. 빌드는 래퍼로만 한다

```bash
python3 scripts/build_ppt.py <build.js>
```

`node build.js`로 직접 빌드하지 않는다. 래퍼가 다음을 순서대로 강제한다.

```
[0/5] 레퍼런스 확인
[1/5] brandlogy_lint   슬라이드 카피 검사      → ERROR면 여기서 중단
[2/5] node 빌드   pptxgenjs 실행
[3/5] ppt_lint    코드·좌표 검사          → ERROR면 완료 아님
[4/5] PNG QA      soffice로 렌더해 눈 확인
[5/5] 실렌더      macOS + PowerPoint 있으면 실제 렌더 (--fast면 생략)
[6/6] 교차검수    사람이 눈으로 보라는 안내. 빌드를 차단하지 않는다 (--fast면 생략)
```

**ERROR가 1건이라도 있으면 그 PPT는 미완성이다.** 0으로 고쳐 다시 빌드한다.
WARN은 자동으로 통과되지만 "개념 슬라이드라서 정상"이라며 눈으로 확인하지 않고 넘기지 않는다.
특히 "시각화 0" 경고는 게으름의 신호다.

[6/6]은 만든 사람이 자기 결과물을 자기 눈으로 통과시키는 것을 막으라는 안내다.
자동 판정이 아니라 문구만 띄우며, 빌드를 차단하지 않는다.
카피가 좋은지, 레이아웃이 매번 다른지, 카드 글자가 잘리지 않았는지는 코드가 못 본다.
가능하면 만들지 않은 사람에게 렌더 PNG를 보여주고 판정을 받는다.

빠른 반복이 필요하면 `--fast`로 [5/5]·[6/6]을 건너뛸 수 있다.

## 2. 카피를 먼저 확정한다

헤드라인·서브타이틀·소제목·SO WHAT·라벨·칩까지 **슬라이드의 모든 글자**를
디자인 전에 확정한다. 디자인하면서 즉흥으로 문구를 짓지 않는다.

카피 기준:
- **메타포 없이 한 번에 이해된다.** 비유로 돌려 말하지 않는다
- **입말로 읽힌다.** 소리 내 읽어 걸리는 곳이 없다
- **단위와 주어가 있다.** "크게 늘었다"가 아니라 "3년 만에 2.4배"
- **So what까지 간다.** 사실 진술이 아니라 결론
- **End Benefit에 닿는다.** "우리가 무엇을 한다"가 아니라 "그래서 읽는 사람이 무엇을 얻는다"

금지: 줄표(— –), 이모지, 원형숫자, "솔직히" 류 강조 도입부, 번역체, 부정과 긍정을 기계적으로
대구시키는 문장의 반복.

## 3. 시각화는 기본값이다

"PPT 만들어줘" 한마디만 와도 **시각화 총동원이 기본**이다. 매번 요청받지 않는다.

- 차트·도식·플로우·분기·사이클·매트릭스·인포그래픽 **+ 사진·목업**
- 텍스트 카드로 설명할 것을 목업이나 사진으로 **보여줄 수 있으면 그렇게 한다**
- 개념·구조 슬라이드도 도식으로 만든다. 텍스트 카드만 줄줄이 나열하지 않는다
- 모든 차트에 수치를 표기한다 (`showValue` 또는 `showPercent`)
- 차트를 이미지로 넣었으면 **그 이미지를 단독으로 열어** 내부 라벨과 데이터점이 겹치지 않는지 확인한다.
  통짜 슬라이드 렌더로는 이미지 내부가 보이지 않는다
- 채팅 목업에는 아바타·헤더·입력창까지 넣어 완결된 화면으로 만든다. 아바타 이미지는 각자 준비한다

## 4. 빌드 전후로 통과하는 10가지

1. **카피를 먼저 확정한다.** 즉흥 작성 금지
2. **정본 템플릿 복사로 시작한다.** 빈 파일에서 즉흥으로 짜지 않는다
3. **레이아웃 판을 직전 슬라이드와 다르게 한다.** Box System 7패턴을 번갈아 쓴다. 같은 2단 구조 반복은 게으름
4. **흰 카드 안에 또 흰 박스를 넣지 않는다.** 색과 그림자로 구분한다.
   요소끼리 붙거나 겹치지 않게 여백을 준다. 텍스트 상자는 텍스트 실제 높이에 맞춘다.
   **모든 `addText`는 `valign: "middle"`** (안 지키면 ERROR)
5. **이모지 0개** (`📁` `💬`만 예외) · **원형숫자 금지** · **줄표 금지** (콜론·쉼표·물결로)
6. **대제목은 존댓말 평서문 + 마침표.** 헤드라인 26pt, 챕터 라벨은 "NN · 카테고리"
7. **승인 팔레트만 쓴다.** 즉석 hex, 특히 즉석 파란 틴트는 ERROR다. 강조색은 오렌지 1색이고 글자에는 쓰지 않는다
8. **카드는 선 없이 그림자만** · 배경은 전 슬라이드 · SO WHAT 띠 유지 · 페이지 번호는 자동 필드
9. **ppt_lint ERROR 0 + PNG 눈 확인 + 실제 PowerPoint 렌더 확인.**
   LibreOffice 렌더는 폰트 계산이 PowerPoint와 달라 글자 겹침·잘림을 놓친다.
   오타는 렌더 이미지 말고 pptx의 `<a:t>` 실문자를 뽑아 확인한다
10. **차트·도식 우선.** 모든 차트에 수치 표기

## 5. 작업 순서

| 단계 | 하는 일 |
|---|---|
| **P1 골격** | 핵심 질문 → 피라미드 구조 → 상황·복잡·해결 흐름 → 슬라이드마다 결론형 제목 |
| **P2 시각화 매핑** | 메시지마다 어떤 시각화가 맞는지 결정 → Box 패턴 선택 → 데이터·출처 정리 |
| **P3 좌표 검증** | 충돌 확인, 콘텐츠 최대 y 6.05 이내, 12컬럼 정렬 |
| **P4 빌드** | 정본 템플릿 복사 → 데이터·문구만 교체 → `build_ppt.py` |
| **P5 검증** | ppt_lint ERROR 0 → PNG 확인 → 실렌더 확인 → 실문자 오타 확인 |
| **P6 저장** | 결과물을 버전명(`vNN-주제.pptx`)으로 보관. 확정되면 `promote_ppt.py`로 정본 승격 |

## 6. 코드가 못 잡는 것 — 내보내기 전 자문

코드는 좌표와 금지 문자를 잡는다. 아래는 사람이 판단해야 한다.

- 카피가 기준(메타포 없이 즉시 이해 / 입말 / 단위·주어 / So what / End Benefit)을 통과했나
- 레이아웃 판이 직전 슬라이드와 다른가. "지난번과 같은 그림 아닌가"
- 승인 팔레트 밖 색이 섞이지 않았나. 강조색이 1개인가
- 밀도는 맞나. 카드 위쪽에만 몰려 있거나 아래가 비어 있지 않나
- 실제 PowerPoint에서 카드 글자가 겹치거나 잘리지 않나
- "전부 고쳐" 지시였다면 `coverage_ledger.py`로 전 항목을 나열하고 각각 [손봄 / 유지(이유)]를 채웠나
