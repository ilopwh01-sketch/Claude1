# GATES.md : 이 번들의 코드 게이트 전수 설명서

## 1. 한 줄 요약

이 번들의 PPT는 사람이 눈으로 보고 "괜찮네" 하는 것으로 완성되지 않는다. `ppt_lint.py`, `brandlogy_lint.py`, `writing_lint.py` 세 개의 린터가 빌드 산출물(build.js 소스 + 실제 .pptx XML)을 기계적으로 검사하고, **ERROR가 1건이라도 남아 있으면 그 PPT는 미완성**이다. 빌드 래퍼 `build_ppt.py`는 ERROR가 있으면 PNG 생성, 미리보기, 완료 보고 단계로 아예 넘어가지 않게 막는다.

WARN은 다르다. WARN은 코드가 확신할 수 없는 근사 판정이라 오탐이 섞인다. WARN은 빌드를 막지 않지만 **PNG를 눈으로 확인한 뒤에** 넘어가야 한다.

> 원칙 하나: "내 눈에 괜찮아 보인다"는 "통과했다"가 아니다. 통과 판정은 린터가 한다.

## 2. 실행 방법

### 2-1. 정본 경로 (권장)

```bash
python3 scripts/build_ppt.py <build.js>          # 최종 빌드
python3 scripts/build_ppt.py <build.js> --fast   # 반복 수정 중 (PowerPoint 실렌더만 스킵)
```

`node build.js`로 직접 빌드하면 게이트를 전부 우회한다. 하지 마라.

### 2-2. build_ppt.py가 부르는 순서

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| `[0/5]` 레퍼런스 | 참고 이미지로 밀도, 여백, 눈높이 맞추라는 안내 출력 (강제 검사 없음) | 없음 |
| `[1/5]` brandlogy_lint | build.js 안의 따옴표/백틱 문자열 중 **한글이 포함된 것만** 뽑아 임시파일로 만들고 `brandlogy_lint.py` 실행 | ERROR면 즉시 exit 1, node 실행조차 안 함 |
| `[2/5]` node 빌드 | `node build.js` 실행. stdout에서 `Saved: <경로>.pptx` 또는 `완료...: <경로>.pptx`를 정규식으로 찾아 pptx 경로 확보 | 경로 문구가 없거나 파일이 없으면 exit 1 |
| `[3/5]` ppt_lint | `ppt_lint.py <build.js> <pptx>` 실행 | ERROR면 exit 1. PNG/open 단계 차단 |
| `[4/5]` soffice PNG QA | `soffice`로 PDF 변환 후 `pdftoppm -r 130`으로 PNG 생성. 외부 삽입 이미지가 2개 이상이면 첫 장을 4분할 크롭까지 자동 저장 | 변환 실패해도 빌드는 통과, 수동 확인 안내 |
| `[5/5]` PowerPoint 실렌더 | macOS에서 osascript로 실제 PowerPoint를 띄워 PDF 저장 후 PNG화. 원본이 아니라 `__render_<uuid>_` 접두사 임시 복사본만 열고 그 이름만 닫는다 | 실패해도 빌드는 통과. `--fast`나 비 macOS면 스킵 |
| 카피 QA | pptx의 `<a:t>` 실제 문자열을 슬라이드별로 전부 출력 | 오타 판정은 PNG가 아니라 이 실문자로 |

`[5/5]`가 있는 이유: soffice(LibreOffice)는 pptxgenjs `addText`의 폰트 메트릭과 줄바꿈을 PowerPoint와 다르게 렌더한다. soffice에서 멀쩡한 카드 글자가 실제 PowerPoint에서는 겹치거나 잘릴 수 있다. **최종 빌드는 반드시 `--fast` 없이** 돌린다.

### 2-3. 개별 실행

```bash
python3 scripts/ppt_lint.py <build.js> [<out.pptx>]   # pptx를 주면 실측 게이트(#19·#24·#25c·#26·#27·#28b)가 켜진다
python3 scripts/brandlogy_lint.py <카피.txt>
echo "카피 한 줄" | python3 scripts/brandlogy_lint.py -
python3 scripts/writing_lint.py <글.txt>
echo "글" | python3 scripts/writing_lint.py -
```

세 린터 모두 ERROR가 있으면 exit 1, 없으면 exit 0으로 끝난다. CI에 물릴 때 이 종료코드를 쓰면 된다.

> **pptx 인자를 주는 것이 기본이다.** pptx 없이 build.js만 검사하면 ppt_lint는 좌표를 JS 소스에서 추정하는 폴백 모드로 돈다. 헬퍼 함수로 그린 카드를 못 읽어 가짜 경보가 뜨고, 반대로 실측으로만 잡히는 결함(#26, #27, anchor 상속)은 아예 검사되지 않는다.

## 3. ppt_lint ERROR 전수표

빌드를 물리적으로 막는 항목이다. 표의 "판정 조건"은 코드에 박힌 실제 수치다.

| # | 이름 | 판정 조건 | 고치는 법 | 왜 있나 |
|---|---|---|---|---|
| 0b | 도형 id 중복 | 한 `slideN.xml` 안에서 `<p:cNvPr id="…">` 값이 중복 | `fix-slidenum.py`가 실제로 호출되는지 확인 (id 재배정 담당) | 중복 id는 PowerPoint "복구" 창을 띄운다. pptxgenjs가 슬라이드번호 자리표시자 id를 25로 하드코딩해서, 도형이 25개를 넘는 밀도 슬라이드에서 충돌한다 |
| 1 | 줄표 | 본문에 `—`(em dash) 또는 `–`(en dash) 포함 | 콜론(:), 쉼표(,), 물결(~)로 교체 | 이 디자인 시스템의 고정 표기 규칙. 줄표는 한글 슬라이드에서 폭이 튀고 AI 티가 난다 |
| 2 | 원형숫자 | `①~⑳ ⓪ ❶~❿ ㉑~㉟` 중 하나라도 포함 | 도형 원 + 일반숫자(1, 2, 3)로 그린다 | 원형숫자 글리프는 폰트마다 크기와 베이스라인이 달라 정렬이 깨진다 |
| 3 | 이모지 | `📁`(U+1F4C1), `💬`(U+1F4AC) 외 이모지 | 제거하거나 도형/아이콘으로 대체 | 이모지는 렌더러마다 모양이 달라 디자인 통제를 잃는다. 폴더와 말풍선 둘만 기능적 아이콘으로 예외 |
| 4 | 자동 슬라이드번호 누락 | build.js에 `slideNumber` 문자열 없음 | `s.slideNumber = {...}` 사용 | 고정 텍스트로 번호를 박으면 슬라이드 순서를 바꿀 때마다 전부 어긋난다 |
| 5 | fix-slidenum 누락 | build.js에 `fix-slidenum` 문자열 없음 | `writeFile().then()` 안에서 `fix-slidenum.py` 호출 | 0b의 id 중복 방지 및 번호 위치 보정 담당 |
| 6 | 배경 이미지 누락 | build.js에 `Background_` 문자열 없음 | 전 슬라이드에 배경 이미지 `addImage` | 배경이 빠진 슬라이드 한 장이 덱 전체를 아마추어로 만든다 |
| 6b-1 | 폐기 배경 | build.js에 `Background_claudelogo` 포함 | `Background_paperlogy.jpg`만 사용 | 폐기된 팔레트/배경 조합. 섞이면 덱 톤이 무너진다 |
| 6b-2 | 폐기 팔레트 hex | build.js **또는 본문 HTML**에 `D97757 292524 6B6862 F4F2EE 8A8378 DAD6CE E7E2DE F4EEE8 D9A38D A8A29E 8B857D C8BEB4` 중 하나 | 승인 팔레트(§7)로 교체 | 코랄/차콜/웜그레이/베이지 계열 폐기색 전체. 본문 HTML을 검사 안 하던 시절이 가장 큰 구멍이었다 |
| 6b-3 | 본문 HTML 검사 불능 | `/tmp/...body....png`를 addImage 하는데 `BODY_HTML: <경로>` 주석이 없음. 또는 그 경로 파일이 없거나 열리지 않음 | build.js에 `// BODY_HTML: /경로/body.html` 주석을 넣고 파일을 남겨둔다 | HTML을 PNG로 구워 넣으면 색 검사를 우회할 수 있다. 검사 불능 상태로는 빌드를 허용하지 않는다 |
| 7 | 로고 텍스트 추가 | `addText("...brandlogy...")` 패턴 (대소문자 무시) | 삭제 | 로고는 배경 이미지에 이미 들어 있다. 텍스트로 또 얹으면 이중 로고 |
| 8 | 차트 수치 미표기 | `addChart(` 개수 > `showValue:true`/`showPercent:true` 개수 | 모든 차트에 `showValue: true` 또는 `showPercent: true` | 수치 없는 차트는 "대충 그린 그림"이다. 읽는 사람이 값을 물어야 하면 실패 |
| 8b | 폐기된 옛 블루 | `4F6EF1 0014D3 7E94F5 A8B7F8 DDE3FB F8F9FF 1C6DD0 0B2E4F 5B9BD5 A9C9E8 DBE9F6 F1F6FB` 중 하나 | 클라인 블루 체계로 교체 | 이전 세대 형광블루와 딥네이비. 새 팔레트와 섞이면 파랑이 두 종류로 보인다 |
| 8f | 오렌지 글자색 | `addText(...)` 호출 안에 `color: "#FF7A00"` 또는 `color: C.accent` | 텍스트 강조는 `002FA7`/`001C64`로. 오렌지는 탭, 바, 면, 밑줄 등 비문자 요소에만 | 밝은 배경 위 `FF7A00`의 대비는 약 2.4:1로 WCAG 대형 텍스트 기준 3:1에 미달한다 |
| 8c | 화살표가 카드 경계 침범 | `endArrowType`이 달린 `ShapeType.line`의 x구간이 `box()` 카드 x구간과 교차하는데 완전 포함은 아님 (y가 카드 세로범위 ±0.10in 안일 때만) | 화살표를 박스 사이 gap 안에만 두거나, 박스 안에 완전히 넣는다 | 화살표가 카드 테두리를 뚫고 지나가면 도식이 지저분해진다. gap 배치와 완전 포함은 통과시켜 오탐을 줄였다 |
| 8d | 원과 옆 텍스트 세로중심 불일치 | 같은 y 기준식을 쓰는 `ShapeType.ellipse`와 직후 `valign: middle` 텍스트의 세로중심 차이 **> 0.04in** | 원 `y = (텍스트 y) + (텍스트 h)/2 - (원 h)/2` | 불릿 원에 `+0.05` 같은 임의 오프셋을 주면 원만 위나 아래로 뜬다. 눈에 바로 걸린다 |
| 8e | 텍스트가 삽입 이미지 위에 겹침 | 같은 슬라이드 안에서 addImage 박스(배경, 목업 제외, 폭 11.0in 이하)와 addText 박스가 **가로 겹침 > min(폭)의 60%** AND **세로 겹침 > 0.2in** | 캡션과 라벨은 이미지 밖으로. 여백 확보 | 요소끼리 붙거나 겹치지 않는 것이 디자인 기본이다. 폭 11in 초과 전면 배경 인포그래픽 위 라벨은 정상이라 제외 |
| 8g | 카드 안 큰 이미지 중앙 이탈 | 폭 5.0in 초과 카드 안에 콘텐츠 이미지가 **정확히 1개**이고 그 폭이 카드 폭의 50% 초과일 때, 이미지 중심 x와 카드 중심 x 차이 **> 0.2in** | 이미지 x를 카드 중심 기준으로 재계산 | 중앙정렬 의도가 명확한 배치에서 오프셋이 붙어 한쪽으로 쏠리는 결함. 작은 좌측 이미지는 비중앙 의도일 수 있어 검사 대상에서 뺐다 |

## 4. ppt_lint WARN 전수표

**WARN은 빌드를 막지 않는다. 대신 PNG를 눈으로 확인한 뒤 넘어가라는 신호다.** 코드가 근사로 판정한 것이라 오탐이 섞여 있고, 그래서 사람의 눈이 최종 판정자다. WARN을 무시하고 "정상"이라 선언하는 것이 가장 흔한 실패 패턴이다.

## 6. writing_lint : PPT 밖 일반 글쓰기용

## 8. 자주 걸리는 것 TOP 5와 해결법

### 1위. `#28` valign middle 누락

**증상:** `#28 valign middle 아닌 addText 37건` 처럼 건수가 통째로 뜬다. `addText` 하나하나가 다 걸리기 때문에 첫 빌드에서 가장 많이 나오는 ERROR다.

**해결:** 모든 `addText` 옵션에 `valign: "middle"`을 넣는다. 헬퍼 함수를 하나 만들어 거기서 기본값으로 밀어 넣는 것이 가장 확실하다.

```js
const T = (s, text, o) => s.addText(text, { valign: "middle", ...o });
```

주의할 것 둘: (a) 이 게이트는 js 검사와 pptx 실측 검사가 따로 있어서, 레이아웃/마스터에 anchor를 숨기는 우회가 안 통한다. (b) `margin`을 배열로 주면서 상하 값을 다르게 하면 `#28-c`에 걸린다. 스칼라 하나로 주는 것이 안전하다.

### 2위. `#17` 시각화 0

**증상:** `🚨🚨 시각화 0 (addText 12 / 차트0·삽입이미지0·도식화살표0) = 빌드 차단`

**해결:** roundRect 카드와 칩과 배지를 아무리 예쁘게 배치해도 시각화로 인정되지 않는다. 다음 중 최소 하나를 실제로 넣어야 한다.

- `addChart` 네이티브 차트 (그리고 `showValue: true`를 잊지 말 것, 안 넣으면 #8에 걸린다)
- matplotlib/PIL로 렌더한 PNG를 `addImage` (배경, 목업 파일명은 제외되니 주의)
- `endArrowType`이 달린 도식 화살표 (분기, 플로우)

`addText`가 8개 미만인 표지와 전환 슬라이드는 자동 예외다. 한 장짜리 요청이라고 차트를 빼는 것이 이 게이트가 잡으려는 바로 그 패턴이다.

### 3위. `#14` 승인 팔레트 밖 파란 틴트

**증상:** `허용 팔레트 외 '파란 계열 틴트' 3개(2B4C9E, 6B84CC, C4D0EC)`

**해결:** 밝기 단계가 더 필요하다고 느껴서 즉석으로 hex를 만든 경우가 대부분이다. 승인 블루는 `002FA7 / 001C64 / 4D6DC1 / 99ACDB / D9E0F2 / EAEEF8` 6단계로 충분히 계조가 있다. 부족하면 투명도(`transparency`)나 중립 회색과의 조합으로 푼다. **새 hex를 만들지 마라.** 상수 객체 하나에 팔레트를 모아두고 거기서만 꺼내 쓰면 재발하지 않는다.

### 4위. `#25` 텍스트 박스가 텍스트보다 큼 / 박스끼리 겹침

**증상:** `텍스트보다 큰 텍스트 박스 5건 (예: y2.40 박스 h1.20 vs 텍스트 실높이 ≈0.35)` 또는 `텍스트 박스끼리 겹침`

**해결:** 박스 높이를 "넉넉하게" 잡는 습관이 원인이다. 공식대로 계산한다.

```
h = 줄수 × (fontSize / 72) × 1.25   (+ 0.1in 이내 여유)
```

카드 안에 텍스트를 세로로 배치할 때는 **박스를 균등 분할하지 말고**, 각 텍스트의 실높이를 먼저 구한 뒤 그 그룹을 산술 중앙 정렬한다. 박스가 텍스트에 딱 맞으면 `#28`의 middle이 곧 디자인 의도 그대로가 되어, 두 게이트가 동시에 풀린다.

### 5위. `#19` / `#24` / `#26` / `#27` 카드 여백 4형제

이 넷은 같은 뿌리다. **카드 크기를 먼저 정하고 내용을 나중에 넣어서** 생긴다.

| 게이트 | 증상 | 방향 |
|---|---|---|
| #19 | 하단 45% 초과 빔 | 내용이 위에 몰림. 카드 높이를 줄이거나 본문을 늘린다 |
| #24 | 하단 패딩 0.10in 미만 (다크는 0.25in) | 반대로 바닥에 딱 붙음. 내용을 위로 올린다 |
| #26 | 내부 세로 gap 0.60in 초과 | 요소 사이가 성김. 세로 재분배 |
| #27 | 우측 35% 이상 빈 기둥 | 내용이 앞쪽에서 끝남. 우측까지 채우거나 카드 폭을 줄인다 |

**해결 순서:** 내용 블록의 실제 높이와 폭을 먼저 합산하고, 그 합에 상하 패딩 0.18in ~ 0.25in을 더한 값을 카드 h로 잡는다. 카드를 먼저 그리고 내용을 채우면 반드시 넷 중 하나에 걸린다. 그리고 이 네 게이트는 **pptx 실측 경로에서만 정확하다.** 반드시 `ppt_lint.py build.js out.pptx` 형태로 pptx를 넘겨서 확인하라(`build_ppt.py`를 쓰면 자동이다).

### 보너스: brandlogy_lint 줄표와 이모지

빌드가 `[1/5]`에서 죽는데 이유를 모르겠다면 대개 이것이다. build.js 안 한글 문자열에 `—`나 이모지가 섞여 있으면 node 실행 전에 막힌다. 콜론, 쉼표, 물결(~)로 바꾸고 이모지는 지운다. 슬라이드에서 이모지가 예외로 허용되는 것은 `📁`와 `💬` 둘뿐인데, 그 예외는 ppt_lint(#3)의 규칙이고 **brandlogy_lint에는 이모지 예외가 없다.** 즉 이 두 개조차 build.js의 한글 문자열 안에 들어 있으면 `[1/5]`에서 걸린다. 아이콘이 필요하면 도형으로 그리는 것이 정답이다.

## 부록: 게이트 요약 카운트

두 가지 방식으로 센다. **규칙 수**는 이 문서의 표 행 수(임계값이 갈리는 항목은 ERROR와 WARN을 각각 1행으로 계산)이고, **코드 호출 지점**은 소스에서 `errors.append` / `warns.append`가 실제로 나타나는 횟수다. 후자가 더 큰 이유는 em dash와 en dash처럼 한 규칙이 여러 줄로 나뉘어 있거나, pptx 실측 경로와 js 추정 경로가 같은 규칙을 각각 구현하기 때문이다.

| 린터 | ERROR 규칙 | ERROR 호출 지점 | WARN 규칙 | WARN 호출 지점 | 자문 체크리스트 |
|---|---|---|---|---|---|
| ppt_lint.py | 34 | 38 | 22 | 24 | 없음 (build_ppt.py가 별도 출력) |
| brandlogy_lint.py | 10 | 11 | 8 | 8 | 12항목 |
| writing_lint.py | 7 | 9 | 9 | 9 | 16항목 |
| **합계** | **51** | **58** | **39** | **41** | **28항목** |

ppt_lint의 게이트 번호는 `0b, 1~28`이며 중간에 `6b, 8b, 8c, 8d, 8e, 8f, 8g, 18b` 하위번호가 들어가 **총 37개 검사 지점**이다. 그중 `#14, #19, #20, #22, #23, #24, #25, #26, #27, #28`은 임계값에 따라 ERROR와 WARN 두 갈래로 갈린다.
